cosmos.gl · the collision force · PR #280

Collision as a constraint: pairwise contacts at every size

With collision on, a dense cluster whose links pull inward never resolved: the leaves of a hub stayed inside each other for as long as the simulation ran. The force is now a constraint that outlives alpha, the springs can no longer ask for overlap, a tick can run several passes, and every path resolves real pairs instead of cell averages, at every graph size.

The symptom

The story that exposed it: seven hubs of size 30, each wired to 60–140 leaves of size 6–16 seeded in a 20-unit disc on top of the hub. Springs at full strength ask for 5 units. Collision is on. On main every cluster collapses into a blob with the leaves stacked on the hub, and stays that way.

Measured on that data with every other force off, the old force plateaued at 1,836 overlapping pairs from tick 2,000 to tick 10,000. Stuck, not slow. Four separate things caused it, and only the first two were tuning. The demo below reproduces the fight at small scale; the renders of the real story are in the pull request.

The cell-average model here is a small-scale stand-in for the deleted grid shader: a point is pushed only when it overlaps the mean of a neighbouring cell's occupants, with the old tenth-of-a-radius cap. Pairwise is the new rule verbatim: project to contact, split by r², cap at one radius. What to expect from this seeded run: the old rules end near 1,900 overlapping pairs, most of them deep; the new rules at their defaults end with a few dozen shallow pairs and at most one deep, because the run is short; 2 passes leave about 20 and 4 passes about 5, none deep. Alpha decays by the engine's rule, ALPHA_MIN1/decay per tick, with decay 450 so a run takes about eight seconds (the hub story uses 5,000); the run ends at 0.001.

Four causes, four fixes

1 · the push cooled with alpha

Collision is a constraint, not a force

before The correction was multiplied by alpha like every other force. Alpha decays exponentially, so roughly the last two thirds of a run sit below a tenth of full strength. Whatever overlap the springs made while hot froze in.

after No alpha factor in the shader, and the integrator applies the correction with friction 1 so it lands in full. simulationCollisionCooling (default 0) is the way back: 1 multiplies by alpha again.

// Optional cooling: alpha^cooling, 1 at cooling 0 (the branch avoids pow(0, 0)).
float cooling = collisionCooling > 0.0 ? pow(max(alpha, 0.0), collisionCooling) : 1.0;
correction *= collisionStrength * cooling;

2 · the springs demanded overlap

Rest lengths floor at the contact distance

before A link rest length shorter than the two radii pulls the pair into overlap every tick. Spring and collision settle wherever they balance, a guaranteed partial overlap by construction. The docs told users to set the link distance clear of the radii.

after While collision is on, the link shader reads the collision module's resolved-size texture and lifts each spring's rest length to Rself + Rother, each radius including padding. A short simulationLinkDistance now means "as close as contact allows".

if (useCollisionRadii > 0.5) {
  float otherSize = texelFetch(sizeTexture, connectedTexel, 0).r;
  float otherRadius = (collisionRadius > 0.0 ? collisionRadius : otherSize * 0.5) + collisionPadding;
  randomMinLinkDist = max(randomMinLinkDist, selfRadius + otherRadius);
}

3 · one pass per tick could not keep up

simulationCollisionIterations

before A hundred springs re-pile a hub every tick. One bounded correction cannot undo that, so the pile only ever got a little looser.

after The whole pass (grid build or all-pairs sweep, then integration) repeats that many times per tick on the freshest positions, like d3's forceCollide.iterations. Cost is linear in the count. NaN and Infinity fall back to one pass.

if (simulationCollision) {
  const requested = this.config.simulationCollisionIterations
  const iterations = Number.isFinite(requested) ? Math.max(1, Math.floor(requested)) : 1
  for (let i = 0; i < iterations; i++) {
    this.points?.swapFbo()
    this.forceCollision?.run()
    this.points?.updatePosition(1)
  }
}

4 · the cell-average model stalls

Pairwise contacts at every size

before The grid pushed a point away from each neighbouring cell's mean. A point got no push unless it overlapped a mean, so two points could sit inside each other while every mean was out of range. Near-coincident points saw the same field and never parted.

after Every overlapping pair is resolved directly. At or below 4,096 points one pass tests every pair. Above it, each grid cell lists up to K real occupants by depth peeling, and the force pass resolves against those. No cell mean anywhere.

// Project the pair to contact; the bigger disc yields less (d3's r² split).
float otherRadius2 = otherRadius * otherRadius;
float overlap = contact - dist;
correction += direction * (overlap * otherRadius2 / (selfRadius2 + otherRadius2));

The contact rule

Both paths resolve a pair the same way, lifted from d3-force. Project the pair to contact along the line between the centers, and split the overlap by r² so the smaller disc yields. Then scale by simulationCollision, where 1 is the full projection and up to 2 over-relaxes. Drag the sliders to see who moves how far.

contact = RA + RB = overlap = contact − d = A moves overlap · RB² / (RA² + RB²) = B moves overlap · RA² / (RA² + RB²) =

The per-pass cap. A point deep in a pile sums many overlapping pairs into one large vector. Each point's summed correction is capped at its own radius per pass. The cap keeps the direction, away from where the pile is densest, and bounds the step, so a pile inflates over a few passes instead of exploding and bouncing back. This is why strength 1 does not always reach contact in one pass: a coincident pair with radii 1 and 100 has a 101-unit gap to close, the r² split hands almost all of it to the small disc, and the cap lets the small disc move one unit per pass, so it takes on the order of a hundred passes.

Coincident points. Two points at the same position have no separation direction. Each pushes along a per-point golden-angle direction (index × 2.39996 rad), so consecutive indices fan out and a stack disperses deterministically rather than by random jiggle.

float maxStep = selfRadius;
float speed = length(correction);
if (speed > maxStep) correction *= maxStep / speed;

Two paths, split at 4,096 points

At or below 4,096 points: exact

One full-screen pass, one fragment per point, looping over every other point. A cheap reject on position alone comes first: no pair can touch beyond Rself + Rmax, where Rmax is the largest effective radius in the graph, computed once on the CPU when the resources are built. Absent points are skipped through the exit texture, never by their position, because a point removed with an animated update keeps its last finite position on the GPU.

Above 4,096 points: depth-peeled slots

The grid stays, with a cell that spans the full contact range (at least 2 × Rmax) so the 3×3 block around a point is exhaustive, and no finer than the many-body force's finest grid (about 2√n per axis), which keeps average occupancy near a quarter point per cell. Each cell lists up to K real occupants. The force pass walks its nine cells' slots and stops at the first empty one, since an exhausted cell peels empty slots for its remaining layers.

How depth peeling lists a cell

Each peel pass draws every point as one vertex into its grid cell. The depth test keeps the point with the smallest per-tick random hash, and a point is eligible only if its hash is larger than the hash the previous pass captured for that cell. K passes therefore yield a uniform random K-subset per cell, re-seeded every pass. A cell with K or fewer points is listed in full and resolved exactly. A denser cell shows each point a fresh random K of its neighbours per pass, so every overlapping pair is reached sooner or later. Step through it:

What stays approximate

Above 4,096 points, a cell holding more than K points is sampled, a fresh random K per pass, so a jammed region converges stochastically. The grid is sized to a quarter point per cell on average, so only a genuine pile is ever sampled, and a pile inflates past K per cell within a few passes.

Under sustained compression past the packing limit, neither version can resolve. In the 50k stress story gravity presses about 84 % area coverage into a disc. The new force halves the worst penetration and starts with far fewer deep overlaps, but spreads the rest into more shallow contacts, and the shallow count keeps growing while gravity keeps pulling.
