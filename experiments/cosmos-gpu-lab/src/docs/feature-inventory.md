# Feature inventory data

The WebGPU migration page reads these rows for the checklist, counts and search results.
Give each feature its production behavior, coverage status, main gap and links to the relevant findings.

## Simulation

| Feature | Production WebGL | Coverage | Evidence and remaining validation |
| --- | --- | --- | --- |
| **Gravity** · `simulationGravity` | A fragment per point computes a linear pull toward the fixed world origin, scaled by strength and simulation temperature (`alpha`). | Partial | The [packaged gravity fixture](#/production-forces?section=try-gravity) checks free points, pins and an absent slot. Both packages also ran gravity with all seven other forces for 100 ticks on million-point dense and hub graphs on M3. Repeat the composed check on a second physical GPU. |
| **Center** · `simulationCenter` | Points blend position sums and count into a 1×1 floating-point target. A second pass divides by count and pulls each point toward the current centroid. | Partial | The [high/low reduction](#/collision?section=doc-findings) fixes the observed dense-center error. Validate longer runs with broader settings on other GPUs. |
| **Many-body repulsion** · `simulationRepulsion` | Up to 4,096 points, checks every pair. Larger graphs use hierarchical grid sums/counts for distant contributions and depth-selected samples of actual points for nearby contributions. | Partial | The [packaged lasso comparison](#/production-forces?section=doc-results-lasso-selection-in-both-storybooks) checks initial expansion and motion inside clusters on 22,500 points. The [eight-force run](#/production-forces?section=doc-results-all-eight-forces-together) measures the dense and hub layouts through tick 100. At 4,095, 4,096 and 4,097 slots on M3, both packages expanded after one tick, kept the pin fixed and preserved the absent slot. The RMS distances between their positions were 0.000010, 0.000012 and 0.000068 graph units. Repeat on another physical GPU. |
| **Link springs** · `simulationLinkSpring` | Adjacency textures describe each point's neighbors. Each fragment accumulates ordered spring corrections using rest lengths, degree bias and strength. Incoming and outgoing passes each integrate before the next starts. | Partial | The [packaged spring replay](#/production-forces?section=try-springs) exercises weighted and missing endpoints. Both million-point packages also preserved every link endpoint through edits, including the hub fixture. Relative frame speed remains open. [Timing](#/production-forces?section=doc-scale-timing) |
| **Cluster attraction** · `simulationCluster` | Additive blending computes a center per cluster. Points read that center or an explicit cluster target and apply global and per-point attraction strengths. | Partial | Both public packages moved clusters toward negative targets for 100 ticks and kept a cluster with a missing or nonfinite target at its centroid. All eight forces also ran together through tick 100 on the million-point graphs. The separate [reduction study](#/integrated-webgpu?section=doc-composed-interaction-native-resident-results) checks sums for 131,328 present points. |
| **Per-point attractors** · `simulationAttractor` | A texture stores target coordinates, strength and target presence. Each fragment pulls its point toward its target; missing targets contribute zero. | Partial | [Signed strengths and missing targets](#/point-attractors?section=recorded-findings) pass through 8,192 points on M3. Validate production setters, transitions and longer runs. |
| **Mouse repulsion** · `simulationRepulsionFromMouse` | A fragment per point computes inverse-square repulsion from the pointer with a minimum-distance clamp. It can run independently of the main simulation. | Partial | The [packaged fractional-pointer replay](#/production-forces?section=doc-results-all-eight-forces-together) holds the right button for eight simulation ticks. Correcting the WebGPU pointer input reduced first-step errors over one backing pixel to 39 of 999,999 live points on each M3 fixture. The maximum was 2.83 pixels. |
| **Collision** · `simulationCollision` | Up to 4,096 points, resolves every pair. Larger graphs use spatial hashing with depth-selected neighbor slots. Radius-weighted positional corrections integrate with friction 1 and may repeat per tick. | Partial | [Hashed collision](#/collision?section=doc-hashed-findings) matches WebGL slot IDs in bounded tests. [Two passes](#/integrated-webgpu?section=doc-composed-interaction) match CPU checkpoints through 32,768 points and cost about 168–173 ms at one million. The WebGPU grid uses the largest resolved point size so an unused default preserves the layout. Both real million-point graphs passed the dense and hub layout checks through tick 100 on M3. [Collision grid sizing](#/production-force-collision?section=doc-results-collision-grid-sizing) |
| **Integration and friction** | A separate pass applies the correction, preserves pinned/absent points and guards invalid or excessive steps; position textures are swapped before writing. | Partial | The [corrected integrator](#/combined-layout?section=doc-gravity-trig) passes selected trajectories. Verify the numerical guards with all production forces. |
| **Cooling and lifecycle** | CPU scheduling updates alpha, controls stepping/pause/resume and emits lifecycle callbacks. | Partial | [Two 5,000-tick full-force runs](#/integrated-webgpu?section=doc-composed-interaction) stayed stable and reheated at 8,192 points. Exercise production callbacks and long runs at larger sizes. |
| **Pinning and dragging** | Pin status prevents integration from moving a point; dragging writes its position through a GPU pass. | Partial | In the packed Deck app, real drags in the main view and quarter-scale thumbnail moved point 0, released its pin and left it pickable at the new position. Both graph ownership modes also survived the checkpoint and recovery replay on M3. [Host checks](#/integrated-webgpu?section=doc-host-ownership) |
| **Point-count and position updates** | Typed-array positions establish stable indices; NaN marks absence. Rebuilt storage reapplies the CPU pinned-index set; setters can transition coordinates and visual channels. | Partial | The public config-rebuild replay checks setters queued before initialization and setters called from an interruption callback. Both packages applied the latest position in all 12 cases on M3. The sparse transition comparison checks absence and reusing an index at a new position. [Sparse transitions](#/production-graph-api?section=try-sparse-transition) |

## Points

| Feature | Production WebGL | Coverage | Evidence and remaining validation |
| --- | --- | --- | --- |
| **Circle primitive** | A point sprite's fragment shader computes circular coverage. | Partial | The [packaged Points replay](#/production-points?section=doc-results) checks fractional diameter, center and pixel ratio. A 32 CSS px circle at a tile boundary and [a curve crossing a point](#/production-graph-api?section=try-curved-link-crossing) check the sprite during style and depth changes. |
| **Other shapes** | Distance calculations define square, triangle, diamond, pentagon, hexagon, star and cross; “none” disables the shape. | Partial | All eight shapes matched every RGBA byte across 26 [packaged frames](#/production-points?section=doc-results) per adapter on M3 and SwiftShader. The fixture uses opaque fills and a fixed camera. It does not establish picking for every moving shape. |
| **Colors, sizes and opacity** | Per-point attributes and global uniforms control color, diameter, alpha and zoom scaling. | Partial | The [point-only style replay](#/production-graph-api?section=try-point-style-updates) checks an interrupted change, painted diameters, endpoint gradients and edge clicks at both pixel ratios. WebGPU continues from the displayed size and color. The previous WebGL target is the restart value on the reference. |
| **Antialiasing and tiny points** | Smooth edge coverage; subpixel points reduce opacity to preserve approximate visual area. | Partial | The [frozen-shape checks](#/point-shapes?section=doc-shapes-evidence-one-device-pixel-boundary-check) kept thin circles visible at 1× and 2×. Strict edge differences remain within the one-device-pixel band on M3. Moving subpixel points need validation. |
| **Inside strokes** | A distance-based inset band follows the shape edge; explicit colors or OKLab-derived shades control its color. | Partial | [Explicit and automatic inset strokes](#/point-shapes?section=doc-method) pass bounded checks. Validate a wider set of colors and transitions. |
| **Images and icons** | A shared texture atlas and per-point UV rectangles provide image sampling, sizing and compositing over the shape. | Partial | A [96 CSS px point image](#/production-graph-api?section=try-curved-link-image-crossing) covers a moving link. The M3 comparison checks opaque, translucent and transparent texels and the click 46 CSS px from center at 1× and 2×. |
| **Highlighting and greyout** | Status textures and separate drawing layers put highlighted points above greyed-out points. | Partial | [Layer order and colors](#/point-rings-greyout?section=doc-effects-evidence) pass bounded checks with retained polygon mask failures. Validate pointer updates and transitions. |
| **Hover, focus and outline rings** | Shader-generated circular bands surround points with configurable widths/colors and state precedence. | Partial | A [stationary cursor](#/production-graph-api?section=try-stationary-hover) receives seven expected hover callbacks as points and camera move. The ring and the complete frames matched at 1× and 2× on M3. Other ring combinations are covered by the [isolated overlay study](#/point-rings-greyout?section=doc-effects-evidence). |
| **Custom drawing order** | Index/rank buffers control which points appear above others. | Partial | [Forward and reverse draw order](#/point-picking?section=doc-picking-evidence) preserve checked IDs. Validate arbitrary reorderings and live updates. |
| **Occlusion optimization** | Opaque cores draw front-to-back with depth writes. A second pass blends edges and translucent portions against that depth. | Covered in isolation | On M3 the WebGPU candidate uses two depth-tested draws for dense overlapping points on its own canvas. All 345,600 pixels in the stock 200,000-point story matched its original single-pass output with opaque and mixed-alpha colors. Picking, sparse points and host-owned depth have separate regression checks. [Packaged point-only results](#/production-points?section=doc-results-point-only-occlusion) |

## Links

| Feature | Production WebGL | Coverage | Evidence and remaining validation |
| --- | --- | --- | --- |
| **Straight links from simulated positions** | Ribbon vertices fetch endpoints directly from the current position texture. | Partial | Both packages [paint and pick a moving link](#/production-forces?section=try-combined) after eight force ticks. The old midpoint returns background. The [packaged Lines cases](#/production-lines?section=doc-results) also exercise gradients, dash patterns and arrows. |
| **Curved links** | Vertex shaders place segmented ribbons along a parameterized conic curve. | Partial | The [packaged Lines replay](#/production-lines?section=doc-results) covers solid curves, endpoint motion and the padded pointer target. The [crossing replay](#/production-graph-api?section=try-curved-link-crossing) checks which object paints on top and owns the click at both pixel ratios. |
| **Widths and zoom scaling** | Per-link widths and uniforms control ribbon thickness and optional zoom scaling. | Partial | [Straight-link checks](#/straight-links?section=doc-automated-cases) cover thin and capped widths. [Curved-link studies](#/curved-links?section=doc-case-evidence) cover selected zooms and pixel ratios. Broader transforms remain open. |
| **Colors and endpoint gradients** | Per-link colors or source/target point colors feed interpolation along the link. | Partial | The packaged [four-link fixture](#/production-lines?section=doc-results) matched the gradient before and after an endpoint moved. Updating only point colors also changed the gradient without a link upload in the [interrupted transition](#/production-graph-api?section=try-point-style-updates). |
| **Solid, dashed and dotted styles** | Fragment shaders calculate stroke coverage and repeating patterns along the ribbon. | Partial | The [packaged Lines checks](#/production-lines?section=doc-results) preserve the wider click target through dash and dot gaps. The [dashed-over-solid crossing](#/production-graph-api?section=try-styled-link-crossing) compares paint and click ownership in both draw orders. Rounding at moving caps can still differ within one device pixel. |
| **Arrowheads** | Shader calculations shape an arrow region and scale it relative to link width and length. | Partial | The [translucent-arrow crossing](#/production-graph-api?section=try-translucent-arrow-crossing) matched both draw orders and per-link controls on M3 and SwiftShader at 1× and 2×. Curved and short-link sizing remain separate cases. |
| **Opacity, antialiasing and blending modes** | Source-over blending produces soft edges/transparency; an optional unblended mode produces opaque hard edges. | Partial | The [solid-link checks](#/straight-links?section=doc-automated-cases) cover antialiased and hard edges and foreground opacity at a crossing. Link greyout remains open. |
| **Distance-based visibility** | Shader opacity changes with the link's on-screen length. | Partial | [Corrected link paint](#/viewer-comparison?section=doc-findings-circles-solid-links-and-clicks-during-motion) matches moving interiors on the two Karate Club styles. Verify the thresholds with more styles and view settings. |
| **Highlight, hover and focus** | Status data changes greyout, hover color and extra width for hovered/focused links. | Partial | On M3 at 1× and 2× both packages returned link 0, link 1, link 1 again to clear focus, then background. At 2× the first stroke measured 1.5 CSS px initially, 2.5 on hover and 4.5 with hover and focus. Across seven states the sampled stroke profiles matched exactly at 1×. Seven edge samples differed by one color level at 2×. [Packaged Lines](#/production-lines?section=doc-results) |

## Interaction

| Feature | Production WebGL | Coverage | Evidence and remaining validation |
| --- | --- | --- | --- |
| **Transitions and point exits** | CPU timing supplies eased progress. Shaders interpolate data and fade disappearing points. | Partial | The [removal replay](#/production-graph-api?section=try-sparse-transition) compares paint, clicks and both area tools through removal and interrupted restoration. The [point-only edit](#/production-graph-api?section=try-point-style-updates) records the two packages’ different restart colors and sizes. |
| **Zoom, pan, fit-to-view and resize** | CPU view transforms feed shader matrices; GPU bounds reductions support fitting the layout. | Partial | Both engines fit a layout spanning two million units, ignored an absent slot and selected each visible point at its projected position. The packed Deck app checks drawing and picking after resizing the shared canvas. [Host checks](#/integrated-webgpu?section=doc-host-ownership) |
| **Point and link picking** | Shape-aware host picking encodes IDs through the draw shader; pointer hover uses circular downsampled coverage and a nearest-hit window. | Partial | The [packaged Lines fixtures](#/production-lines?section=doc-results) returned all 588 expected click targets on M3 and SwiftShader. The current signed packages also returned all 288 trusted million-point targets on M3. The first visible fixed-tick WebGPU click took 14–15 ms. The hub met the relative allowance in both orders. The dense comparison and live frame and click timings remain unassessed. [Timing](#/production-forces?section=doc-scale-timing) |
| **Rectangle and polygon selection** | Both area tools select touching footprints by default. Center mode selects a point on or inside the boundary. | Partial | [Packaged rectangle selection](#/production-graph-api?section=doc-youtube-selection) returned the expected ordered IDs on the moving YouTube graph. On the continuously moving million-point graph, all eight WebGL releases timed out for both reads. WebGPU returned ordered IDs and 1,000 label coordinates at all eight releases, with a median of 251 ms until both reads were ready on WebGPU build `6a6f1ceb`. For fixed-tick long lassos, signed WebGPU `754a02b6` returned the exact ordered IDs and all 1,000 label positions on eight releases. WebGL timed out on the million-point tick-10 release in two async runs. Its blocking control returned all 251,132 expected IDs there. Both packages agreed on the [interrupted size fixture](#/production-graph-api?section=try-point-style-updates). At 1× and 2× the package replay switches modes and checks a 32,771-vertex lasso in both directions. Repeat on other supported adapters. |
| **Position tracking and label sampling** | GPU passes gather selected positions or screen-space samples for CPU consumers. Example text labels are external overlays. | Partial | The packaged WebGPU Graph returned all [1,000 tracked coordinates](#/production-graph-api?section=doc-youtube-selection) at the tested YouTube sizes. The packaged [headless trackers](#/production-graph-api?section=try-headless-trackers) kept independent groups through edits and teardown. Verify screen-space sampling and feedback at scale. |
| **Host rendering and shared resources** | Cosmos can draw into a host render pass with supplied view transforms, shared devices/position resources and host picking. | Partial | The [packed Deck app](#/integrated-webgpu?section=doc-host-ownership-recovering-a-moving-deck-session) restored 65,536 saved positions in both ownership modes after Chrome GPU-process loss on Apple Metal and SwiftShader, and after device destruction in Firefox, WebKit and installed Safari. Qualify another physical GPU family. |
