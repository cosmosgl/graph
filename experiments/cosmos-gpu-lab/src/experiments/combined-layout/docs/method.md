## What this comparison establishes

This experiment isolates force composition and independent evolution. Each lane starts from the
same graph and retains its own positions between ticks. The [current evidence](#/combined-layout/docs/gravity-trig)
records the refined-gravity candidate; [Evidence](#/combined-layout/evidence) distinguishes it
from earlier native and partially corrected controls.

Selected 8,192-point chain, communities and star checks pass the original compatibility budgets.
This is a bounded result for the stated arithmetic, inputs and M3 environment. It is not complete
Graph execution, collision-enabled large-graph acceptance or an independent mathematical/quality verdict.

## One composed tick

```flow
Gravity · Calculate attraction and integrate
Optional center · Reduce the current positions, attract toward the center and integrate
Global repulsion · Build the selected hierarchy and integrate
Incoming springs · Accumulate neighbors in production order and integrate
Outgoing springs · Continue from the incoming result and integrate
Cooling · Decay alpha after the complete tick
```

The WebGL lane imports production GLSL and hosts it through luma v10. The WebGPU lane uses luma
kernels and resident buffers. The CPU compatibility model separately implements scalar float32
operations. Bounds/readback and CPU prediction are outside any GPU-timestamp interpretation.

## Arithmetic candidates

**Refined gravity + rounded steps (`trig`)** is the current compatibility candidate for the
recorded larger matrix. Native f32 and earlier corrections remain selectable controls. Do not
read a native-control failure as a failure of the final candidate, or replace its failed gate
with a close layout metric. Detailed rounding investigations stay in the evidence index.

## Validation and layout observations

Local checks use each stage’s actual GPU input; whole-tick checks compare the uninterrupted CPU
chain from that lane’s tick start. Independent trajectory/layout metrics answer another question.
The first, interval and final checkpoints have numerical verdicts; unvalidated ticks do not.
The alpha-1 probe restores original layouts and cooling, testing residual motion after apparent
settling. Deterministic capture/replay retains the earliest discrepancies.

The reference, acceptance rules, population and limits are listed below. The
[validation workflow](#/validation-workflow) distinguishes compatibility from accuracy, quality and cost.

## Reproduction

Open [Run](#/combined-layout/run). **Recorded control** selects the 8,192-point communities graph, 100 cooling
ticks and refined gravity from the recorded matrix. Step once, inspect the live checks, then
run the schedule and probe at alpha 1. For the recorded 8,192-point result, use the exact
fixture/variant and checkpoint settings in [current evidence](#/combined-layout/docs/gravity-trig).

**Simple case** uses 128 points. **Known boundary** selects the earlier aligned communities
control whose larger whole-tick failure motivated refined gravity. These are comparison inputs,
not promises that every native adapter will reproduce a historical failure. Choosing a preset
replaces the current run; consulting documentation does not. Playback stops at the next safe
boundary and stays stopped until you explicitly run again.

Timing and isolation controls are in the visible **Diagnostics** section of Run. Validation elapsed time is
not GPU execution time. Use the documented frozen-stage and normal-frame studies for cost.
