# How closely does WebGPU follow the original Cosmos?

At the audited revision `93e23212`, changing one link width repacked every point and link. The candidate now routes width-only edits to Lines and point color and size edits to Points. Both modules keep other records on the GPU. A link-only topology edit rebuilds the adjacency and link records while retaining point paint and draw order. A simultaneous point edit or an active transition uses the full update path. [Link-width measurements](../cosmos-gpu-lab/src/experiments/production-lines/results.md#changing-only-link-widths) · [Point-style measurements](../cosmos-gpu-lab/src/experiments/production-graph-api/method.md#change-only-point-colors-and-sizes)

## Differences an application can observe

The focused comparisons use the real WebGL and WebGPU bundles on Apple M3 in Chrome.

- **Transition getters, fixed after the audit.** Halfway through a 1,000 ms transition from radius 4 and width 2 to 20 and 10, WebGPU previously returned the targets. Both packages now return **12 and 6**, which match the measured spans of the point and link in the 1× test. The actual story label's bottom edge moves through y = 122, 114 and 106 CSS pixels at the start, midpoint and end in both engines. [WebGL radius](../../src/index.ts#L1465) · [Paired label and raster regression](../cosmos-gpu-lab/src/experiments/production-graph-api/style-transitions.test.ts)
- **Non-finite friction, fixed after the audit.** A single gravity step with `NaN` friction previously turned all four coordinates of the two-point WebGPU fixture into `NaN`. Both engines now use the shared default of 0.85 at integration. On M3, the rebuilt packages returned identical positions for a gravity step and a paused right-button impulse at 0.85, `NaN`, both infinities, zero and −0.5. With gravity 0.25 the point at the origin stayed still and the second point moved from x = 2008 to x ≈ 2008.85 for all three non-finite inputs. [Reference regression](../../test/unbounded-space.test.ts#L1244) · [WebGPU regression](test/forces.test.ts#L22)

## Contributor experience and next changes

1. **Make the public API as readable in an editor.** At the audited revision, counting public instance method declarations with attached JSDoc gave Graph **84/84** in WebGL and **4/78** in WebGPU. For GraphSimulation the counts are **42/42** and **2/32**. These counts include methods marked internal. Carry over array layouts, units and the setter-to-render timing. Describe read freshness and the borrowed buffer lifetime in WebGPU's own terms. Expand multi-operation one-liners where ordering matters, and use one import convention for shared source. [WebGL setter](../../src/index.ts#L559) · [WebGPU setter](src/graph.ts#L251) · [Shared imports in Graph](src/graph.ts#L5) · [Shared imports in GraphSimulation](src/simulation.ts#L3)
2. **Then simplify the simulation coordinator.** Expose the ordered tick and share backend-independent rules such as the collision cutoff and initial position scaling. Keep backend-specific allocation, upload and disposal local. WebGPU constructs its common kernels even for a static scatterplot. Measure startup and first draw with simulation disabled and after enabling it before changing those lifetimes. [WebGL cutoff](../../src/modules/ForceCollision/index.ts#L31) · [WebGPU cutoff](src/modules/ForceCollision/index.ts#L40) · [WebGL scaling](../../src/modules/Points/index.ts#L3736) · [WebGPU scaling](src/simulation-data.ts#L5) · [Kernel creation](src/simulation-kernels.ts#L29)

**WebGPU point quads use the requested diameter.** WebGL reports its device’s point-sprite limit in CSS pixels. WebGPU builds the footprint from triangles, so it has no corresponding point-sprite limit and reports `Infinity` for `Graph.maxPointSize`. The image or shape can determine the diameter. Drawing, point rings and pointer picking use the displayed footprint, and both area queries use the target diameter in `touch` mode or the center in `center` mode. Link width keeps its own limit. [Point drawing](src/modules/Points/draw-points.wgsl) · [Area selection](src/graph.ts)

## Verification

The 3.6.1 shared Graph stories produced five errors when typechecked against the WebGPU entry. Three performance stories requested synchronous position arrays and Area Selection called both synchronous area queries. The same story sources now pass against both public entries. The candidate typecheck includes the shared Graph stories. A separate packed consumer verifies the Deck package. The paired Storybook check drags an actual rectangle and lasso at both pixel ratios and switches the rectangle preset between touch and center. The separate package replay checks both modes for both tools. [Storybook checks](../../scripts/check-storybook-reads.mjs) · [Points comparison](../cosmos-gpu-lab/src/experiments/production-points/results.md) · [Force comparison](../cosmos-gpu-lab/src/experiments/production-forces/results.md)

In Chrome on M3, both previews selected Medium and then Large when the selection moved. Far Point reported the newly loaded distance, Space Wall reported tick 200 after a paused burst, and Steady-State Motion drew its trajectory after the layout formed. On SwiftShader the selection and first two readout stories also passed on both engines. The four-pane WebGPU trajectory exceeded the 180-second software verification window.
